# Contributing

Thank you for contributing.

## Development workflow

1. Create a branch from main.
2. Keep changes focused and reviewable.
3. Update documentation when behavior, structure, or content contracts change.
4. Ensure local checks pass before submitting a pull request.

## Quality gates

Run before opening a PR:

```bash
npm install
npm run build
```

## Content standards

- Keep writing practical and implementation-oriented.
- Avoid generic or unverifiable claims.
- Preserve professional tone across all pages and posts.
- Keep resume-backed facts accurate and consistent.

## Pull requests

PRs should include:

- Short summary of what changed
- Reason for change
- Any screenshots for visual updates
- Notes about content or metadata updates
